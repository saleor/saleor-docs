Saleor limits how many requests you can send, how large a single request can be, and which files you can upload. Saleor Cloud sets some of these limits differently from a self-hosted Saleor. Self-hosted deployments can change the defaults with the environment variables listed below.

## Rate limits

Saleor Cloud **sandboxes** are limited to **120 requests/minute** on the free plan and **2,000 requests/minute** on paid plans. The limit is applied to all API requests, including GraphQL and Storefront API and is calculated for the entire environment, not per individual IP address. You will receive a **HTTP 429** response code if you exceed the limit. The limit resets every 60 seconds and is not a moving window.

Saleor Cloud **production** environments and on-premise deployments have **no rate limiting in place** for the API.

:::note[Excessive traffic on production environments]
If traffic to a production environment, intentional or not, degrades the performance, availability, stability, or security of Saleor Cloud, or puts a disproportionate burden on the shared infrastructure, Saleor may temporarily throttle, rate limit, or reject that traffic to protect the service. Saleor may do this without prior notice when it is needed to prevent or mitigate service degradation. Saleor may notify you by email, through your established communication channels, or in the API response: rejected requests receive HTTP 429, so retry them with backoff.
:::

## Request limits

| Limit | Saleor Cloud | Self-hosted default | Environment variable |
| --- | --- | --- | --- |
| Operations in one batched request | 10 | 1 | `GRAPHQL_BATCH_MAX_COUNT` |
| Mutations in one operation | 10 | 4 | `GRAPHQL_MUTATION_COUNT_LIMIT` |
| Aliases in one operation | 550 | 100 | `GRAPHQL_ALIAS_COUNT_LIMIT` |
| Request duration | 30 seconds | Set by your server | |

A request over any of the first three limits is rejected with HTTP 400 and is not executed. The error message names the limit, for example `Number of batch queries exceeded.` or `Number of aliases exceed the limit of 550`.

## Query cost

The GraphQL API calculates the number of requested objects to determine the cost of a query. The cost is calculated based on the number of objects requested, not the number of objects returned. For example, a query that requests 10 products will cost the same even if there are only 5 products in the database.

Certain fields may impose an additional cost. For example, fields that return unfiltered lists of objects and fields that can return large JSON structures.

Saleor will refuse to execute queries that exceed the maximum cost allowed by the server.

You can find the cost of each query and the maximum cost allowed by the server in the `extensions.cost` field of the response.

```json title="Response" {6,7,8,9}
{
  "data": {
    // ...
  },
  "extensions": {
    "cost": {
      "requestedQueryCost": 5,
      "maximumAvailable": 50000
    }
  }
}
```

#### Example: Query cost calculation

The cost breakdown for the following GraphQL query is as follows:

- Number of products fetched (`products.first`): 10
- Attributes cost: 10 (`products.first`) × 100 (complexity factor) = 1,000
- Variants cost: 10 (`products.first`) × 100 (complexity factor) = 1,000

Total cost:

```
10 (base cost for 10 products)
+ 10 (attributes): 10 (`products.first`) × 1
+ 10 (variants): 10 (`products.first`) × 1
= 30
```

```grapqhl
{
  products(first:10, channel:"default-channel"){
    edges{
      node{
        attributes{
          __typename
        }
        variants {
          id
        }
      }
    }
  }
}
```

## Individual field limits

Fields that use pagination (`first`/`last`/`before`/`after`) are limited to 100 items per page. See [pagination](/api-usage/pagination) for details on how to paginate through results.

## File uploads

### Image size

| Environment | Maximum image size |
| --- | --- |
| Saleor Cloud sandbox | 30 MB |
| Saleor Cloud production | 100 MB |
| Self-hosted default | 10 MB, set with [`MAX_IMAGE_FILE_SIZE`](/setup/configuration#max_image_file_size) |

The limit applies to image upload mutations such as `productMediaCreate`, `categoryCreate`, `collectionCreate`, and `userAvatarUpdate`. A larger image is rejected with the `FILE_SIZE_LIMIT_EXCEEDED` error code.

### File types

Mutations that accept any file, such as `fileUpload` and `digitalContentCreate`, accept only an [allowed list of file types](/security#restricted-file-uploads). Saleor Cloud also accepts PDF files (`.pdf`), which a self-hosted Saleor rejects by default. To allow PDF on a self-hosted Saleor, first serve media files with `Content-Disposition: attachment` as described in [Restricted File Uploads](/security#restricted-file-uploads), then set [`UPLOAD_ADDITIONAL_ALLOWED_MIME_TYPES`](/setup/configuration#upload_additional_allowed_mime_types):

```shell
export UPLOAD_ADDITIONAL_ALLOWED_MIME_TYPES='{"application/pdf": [".pdf"]}'
```
