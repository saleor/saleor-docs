---
title: App Requirements
---

To make an app installable in the Dashboard, you must publish its manifest at a URL that Saleor can access. A register endpoint is conditional:

- [Manifest URL](#manifest-url) - provides the app's metadata.
- [Register URL](#register-url) - receives the app token. Required only when the manifest includes `tokenTargetUrl`.

:::info
We recommend using [Saleor App Template](/developer/extending/apps/developing-apps/app-template.mdx) as a starting point for building your App. It provides all the necessary boilerplate needed to focus on your app's logic.
:::

## Frontend-Only Apps

A frontend-only app runs entirely in the browser, typically inside an iframe in the Saleor Dashboard. You can host its manifest and user interface as static files, without an application backend.

Omit `tokenTargetUrl` from the manifest. During installation, Saleor creates the app and its extensions, but does not create an app token or send a registration request. Because there is no app token to store, the app does not need a register endpoint or an [Auth Persistence Layer (APL)](/developer/extending/apps/architecture/apl.mdx).

The following manifest installs a frontend-only product widget:

```json
{
  "id": "com.example.product-widget",
  "name": "Product widget",
  "version": "1.0.0",
  "permissions": ["MANAGE_PRODUCTS"],
  "extensions": [
    {
      "label": "Product widget",
      "mount": "PRODUCT_DETAILS_WIDGETS",
      "target": "WIDGET",
      "permissions": ["MANAGE_PRODUCTS"],
      "url": "https://example.com/product-widget"
    }
  ]
}
```

Frontend-only apps can still make authenticated GraphQL requests while a staff user has the app open. The Dashboard provides a short-lived access token through [App Bridge](/developer/extending/apps/developing-apps/app-sdk/app-bridge.mdx). Its permissions are limited to the intersection of the app's permissions and the staff user's permissions. For an extension, they are also limited to the permissions declared by that extension. If the app only displays static or public data, omit the permissions or use empty arrays.

Add a backend, `tokenTargetUrl`, and an APL when the app must make authenticated requests without an active Dashboard user, receive webhooks, or perform operations with app permissions instead of the user's permissions. See [Server and Client-Side Calls](/developer/extending/apps/architecture/server-and-client-side-calls.mdx) for the token models.

## Manifest URL

- Method: `GET`
- Response - `JSON` with a valid [App Manifest](/developer/extending/apps/architecture/manifest.mdx)
- Suggested path: `/api/manifest`

Saleor will call this endpoint to get your App metadata. It returns the App's name and description, as well as all the necessary information to register webhooks, permissions, and extensions.

Dashboard and Saleor API will use this endpoint to retrieve information needed to install the App.

To learn more about what Manifest consists of, please check the [Manifest docs](/developer/extending/apps/architecture/manifest.mdx) or explore its [type](https://github.com/saleor/saleor-app-sdk/blob/main/src/types.ts#L67).

If your App is built with [Next.js](https://nextjs.org/), you can use a [helper from @saleor/app-sdk](https://github.com/saleor/saleor-app-sdk/blob/main/docs/api-handlers.md#manifest-handler-factory) that creates a Manifest handler with minimal config.

## Register URL

- Method: `POST`
- Response - status `200`
- Suggested path - `/api/register`

:::info
This endpoint is only required when an app needs its own app token for server-side work. A [frontend-only app](#frontend-only-apps) can omit `tokenTargetUrl` and skip this endpoint.
:::

During the installation of an App, Saleor will call this endpoint if `tokenTargetUrl` is provided in the manifest.

When calling the "register" endpoint, Saleor will add the `auth_token` param to the request body and domain header. The App's job is to save the token and use it to run API calls.

While we suggest `/api/register` path, it can be configured in [Manifest](/developer/extending/apps/architecture/manifest.mdx) with the `tokenTargetUrl` field.

You can write this endpoint on your own, but we recommend using a [helper](https://github.com/saleor/saleor-app-sdk/blob/main/docs/api-handlers.md#app-register-handler-factory) provided by `@saleor/app-sdk`.

To use this helper, you must provide a valid [Auth Persistence Layer - APL](/developer/extending/apps/architecture/apl.mdx), that will handle storing token and domain pairs for your App.
