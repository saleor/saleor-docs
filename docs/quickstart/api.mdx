<div>
  Getting familiar with basic APIs and Webhooks. This guide assumes basic
  knowledge of GraphQL.
</div>

<div>

Communicating with Saleor is done via public and private GraphQL APIs and webhooks:

- **Public APIs**: Used for storefront clients, mobile apps, and other public-facing applications that do not store secret tokens.
- **Admin APIs**: Can be accessed by backend services, [admin dashboards](https://github.com/saleor/saleor-dashboard), apps or backends for front-ends.
- **Webhooks:** Used to notify external systems about events in Saleor, such as order creation, order payment, or order fulfillment.
- **Sync Webhooks:** Allow to modify saleor responses, for when user adds item to cart, webhook would call your backend to for custom price calculation.

GraphQL provides [many benefits](/overview/why-saleor/graphql) and one of them is [tooling](/api-usage/developer-tools) that eliminates the needs for dedicated SDKs.
To keep this guide universal to any technology stack, we will use GraphQL playground, but you can paste the queries to your preferred language or tool.

</div>

<Steps titleSize="h3">
<Step title={"Prepare your store"}>
<div>
<span id="use-sample-dataset" />

Use a store with published products, purchasable variants, and shipping methods configured for your channel. The interactive examples use IDs returned by your store, so they do not need to match the sample IDs.

For an empty local development store, you can [add sample data](/quickstart/running-locally#add-sample-data).
</div>
</Step>

<Step title={"Open GraphQL playground"}>
<div>
<span id="open-graphql-playground" />

Saleor comes with GraphQL pre-installed, which can be accessed in two ways:

**Saleor Dashboard:** The dashboard is available at use ```cmd+'``` to open the playground. All queries will be on behalf of the authenticated user, therefore the queries will be limited to the user's permissions.

**Public playground:** Each instance has ```/graphql/``` endpoint available for public access. For example
```https://{your_store}.saleor.cloud/graphql/```
or ```http://localhost:8000/graphql/```
All queries will be via public access unless app token headers are specified.

Run the public examples directly below after configuring your API URL. The embedded Playground sends anonymous requests and does not accept tokens. Before configuration, the examples show editable placeholder values without executing requests.

Within this walkthrough, successful results fill in the next step’s variables. Run each prerequisite first; the connection check is optional. Rerunning or editing an earlier step clears dependent progress. Refreshing, leaving the page, or changing the API URL resets the walkthrough.

The later order operations require an app token and must be run in a separate GraphQL client.
</div>
</Step>

<Step title={"Add webhook"}>
<div>
<span id="add-webhook" />
Before placing an order, we would like to add a webhook to notify our system about the order so we can
dispatch email, create an export to the ERP system, or any other custom action.

For simplicity of the steps, let's do it via the dashboard:

- Open Saleor dashboard
- Go to _Extentions_ → _Add Extention_ → _Provide details manually_
- App name `My App`
- Enable permissions `HANDLE_CHECKOUTS` and `MANAGE_ORDERS`
- Copy the generated token somewhere safe
- Create a webhook with the following details:
  - Name: `Order webhook`
  - Target URL: For simplicity of the test, go to `https://webhook.site/` and copy the `Your unique URL` value
  - App: `My App`
  - Select event: Asynchronous → `ORDER` → `CREATED`

</div>
<div>
<Tabs>
<Tab value="graphql" title="Subscription query">

```graphql
subscription {
  event {
    ... on OrderCreated {
      __typename
      order {
        id

          streetAddress1
          city
          cityArea
          companyName
          countryArea
          firstName
          country {
            country
            code
          }
          id
          lastName
          postalCode
          phone
        }
      }
    }
  }
}
```

<Step title={"Create an order"}>
<div>
<span id="create-an-order" />

For simplicity of the steps, we will skip the [payment step](/developer/payments/overview) and create an order directly.

This operation requires an app token with `HANDLE_CHECKOUTS`. Use a separate GraphQL client, such as your store’s `/graphql/` playground, and add the app token copied in the previous step to its headers. The embedded Playground does not accept tokens. Replace the sample checkout ID below with the ID returned when you created your checkout.
If you forgot or lost a token from the previous step, you can create another one in the app settings.

After executing the mutation, you should be able to see the order in the dashboard and a payload in the https://webhook.site/ with the order details provided in the subscription query.

Note: [`orderCreateFromCheckout`](/api-reference/orders/mutations/order-create-from-checkout) mutation requires the App Token. To transform the checkout on behalf of the customer, use [`checkoutComplete`](/api-reference/checkout/mutations/checkout-complete) mutation.
</div>
